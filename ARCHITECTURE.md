# Архитектура

Карта проекта. Её правит владелец; код подгоняется под неё. Стрелки проверяет ESLint
(`eslint.config.js`), контракты — `tsc`, запреты — тесты.

## Модули

| Модуль         | За что отвечает                                         | Чего не знает                      |
| -------------- | ------------------------------------------------------- | ---------------------------------- |
| `telegram.ts`  | Говорит с Telegram и решает, чьё сообщение принять      | Orca, юниты, хранилище             |
| `chat.ts`      | Пишет в чат агента Orca и ждёт ответ                    | Telegram, юниты, хранилище         |
| `orca.ts`      | Вызывает CLI Orca                                       | Telegram, чаты, юниты              |
| `worker.ts`    | Связывает всё: юниты, опрос ботов, ходы, запросы панели | Как устроены Telegram и сокет Orca |
| `panel.tsx`    | Интерфейс: показывает состояние и шлёт запросы воркеру  | Всё, кроме контрактов              |
| `contracts.ts` | Типы на границе панели и воркера                        | Реализацию                         |

## Стрелки

```
panel.tsx ──► contracts.ts ◄── worker.ts ──► telegram.ts
                                   ├───────► chat.ts
                                   └───────► orca.ts
```

- `telegram.ts`, `chat.ts`, `orca.ts`, `contracts.ts` не импортируют другие модули плагина.
- `panel.tsx` импортирует только `contracts.ts` и не использует Node.
- `worker.ts` — единственный, кто знает всех.

## Контракты

| Граница             | Что ходит                                                                                  |
| ------------------- | ------------------------------------------------------------------------------------------ |
| панель → воркер     | запросы `state`, `projects`, `unit.save`, `unit.connect`, `unit.disconnect`, `unit.remove` |
| воркер → панель     | событие `changed`; ответ на любой запрос — `State` (список `Unit`)                         |
| `telegram` → воркер | `Message`: чат, номер сообщения, тема форума, текст с именем автора                        |
| `chat` → воркер     | `Entry[]`: сообщения агента, ошибки и вопросы, ждущие ответа                               |

## Состояние

| Что                                | Где лежит                       | Кто меняет         |
| ---------------------------------- | ------------------------------- | ------------------ |
| Юниты (имя, роль, проект, чат)     | хранилище плагина, ключ `units` | только `worker.ts` |
| Токены ботов                       | секреты плагина, `token:<id>`   | только `worker.ts` |
| Позиция в очереди Telegram         | хранилище, `offset:<id>`        | только `worker.ts` |
| Отправленный, но не отвеченный ход | хранилище, `turn:<id>`          | только `worker.ts` |
| Очередь входящих сообщений         | серверы Telegram                | Telegram           |
| Разговор с агентом                 | Orca                            | Orca               |

## Запреты

- Сообщение не доходит до агента дважды: позиция в очереди сохраняется до хода, отправка в чат не повторяется.
- Ответ на отправленный ход не теряется при перезапуске плагина и при обрыве связи с Orca.
- В личных сообщениях бот не отвечает никому.
- Токен не попадает в текст ошибок.

## Решения

- **Сокет Orca вместо официального API** — официального способа написать в чат агента нет; замена отслеживается в
  [#11](https://github.com/kimsanbaev-karim/Agents-Bots-for-Telegram/issues/11).
- **Очередь держит Telegram, а не плагин** — перезапуск ничего не теряет, и в памяти процесса нечему пропадать.
- **Без сборки** — Orca загружает TypeScript как есть.
